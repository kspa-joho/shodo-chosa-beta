1. プロジェクト背景と目的

大規模災害時、通信遮断下にある現場から、確実に被害状況を事務所へ届けるための建設コンサルタント専用ツール。鹿児島県測量設計業協会の情報専門部会が主導して開発。

  • Local-First: サーバー・DB不要。ブラウザとHTMLファイル単体で動作する。
  • Bucket Relay: データ連携は物理的なファイル移動（JZIP形式）で行う。
  • Resilience: 意匠よりも、数千件のデータを扱っても落ちない堅牢性を最優先する。

2. 開発運用ルール（SSOT）

  • Phase管理: 会議の局面管理番号（X.X）。package.jsonのphaseフィールドを正とする。
  • 永遠のβ版: 現場フィードバックにより開発は永続する。「完成」と決めつけない。
  • Spec as Code: 本ファイル（src/spec.html）はプロジェクトの唯一の正解情報（SSOT）である。
  • コード提示ルール: 省略不可・全文表示・変更ファイルのみ・圧縮不可。最適化と意匠変更は判断を仰ぐ。毎回 package.json と spec.html を提示する。

5.3 Excel帳票出力仕様（Phase 13.41追加）

  • 出力単位: 1件＝1xlsx（P1・P2・P3縦並び、165行、template.xlsxを複製）。
  • 個別出力: 右ペインの「帳票Excel出力」ボタン → generateExcel() → 1件分xlsxをそのままダウンロード。
  • 一括出力: データベースタブの「一括Excel出力」ボタン → batchExcel()。チェック件数分のxlsxをJSZipでまとめて report_batch_N件_YYYYMMDD.zip としてダウンロード。
  • テキスト書き込み: JSZipでsharedStrings.xmlとsheet1.xmlを直接書き換え（ExcelJS不使用）。セルマッピングはP1〜P3対応表に準拠。
  • 画像書き込み: JSZipでdrawing1.xmlを直接書き換え。xdr:sp（Shape）→xdr:oneCellAnchor + xdr:pic（Picture）に変換してblipFillで画像を参照。drawing1.xml.relsも再構築。
  • template.xlsx埋め込み: build.js がbase64変換してHTMLの hidden inputに埋め込む。{{XLSX_TEMPLATE}}プレースホルダーで置換。
  • Content_Types.xml: jpeg MIMEタイプ定義を自動追加（ないとExcel修復エラーになる）。
  • 位置図: captureMapFinal()（PDF帳票と共通）で全体図・拡大図を生成してichizu_zentai/kakudaiに差し込む。
  • ExcelJS廃止理由: writeBuffer()がdrawing1.xml等を削除・Print_AreaのNaN変換が発生しExcel修復エラーとなるため廃止。JSZip直接操作方式に変更。

5.4 updateValue の再描画制御（Phase 13.38修正）

  • updateValue(key, f, v): データのみ更新・再描画なし。
  • updateValueAndRefresh(key, f, v): データ更新＋renderDatabase()。
  • DBタブのinputはoninputでupdateValue()、onblurでrenderDatabase()を呼ぶ。

5.6 帳票出力ロジック（PDF）

  • SVGテンプレート方式。report_p1〜p3.svgのrectをforeignObjectに置換してテキストを流し込む。
  • fillPhotoBook photo_comment インデックス修正済み（Phase 13.36）。
  • テキスト配置（replaceRectWithText、Phase 13.43修正）:
    • 1行枠（枠の高さが基準文字サイズ10の2.2倍未満。p1〜p3の災害番号・所属名・被災場所・路線名・被災日・延長・高さ・座標・会社名・電話・FAX・氏名・E-mail、P2の全景・近景コメント枠。高さ約11〜14pt）：余白0・行の高さ1・縦中央・折り返しなし（nowrap）・overflow:visible。文字サイズは10を基準とし、canvasのmeasureTextで測った幅が枠幅（左右余白4ずつを除く）を超える場合のみ、幅に収まるまで縮小する（下限4）。改行は空白に置換する。
    • 複数行枠（コメント・拡大状況・特記状況・対策概要・P3の写真コメント等）：従来どおり。左上寄せ・行の高さ1.2・overflow:hidden・面積ベースの自動縮小（下限4）。
    • ハイフン・チェック印（「-」「✓」）：従来どおりSVG textで描画。空文字は枠ごと削除。
    • 修正の経緯: 旧実装は行の高さ1.2（12px）＋上余白2pxで配置しており、高さ約11.3ptの1行枠では文字の下側が枠外に出て、overflow:hiddenで切れる／罫線と重なる不具合があった（意見箱：萩原技研・池田コンサルタント、Android）。あわせて、長文だけ縮小されて行ごとに文字サイズ・位置がばらつく問題があった。フォント（Androidの Noto Sans CJK JP 等）により縦位置が±1pt程度変わるため、1行枠はクリップしない方針とした。
    • 見た目の変更点: 1行枠の文字は、幅に収まる限り10で統一される（従来は短い値でも枠の面積次第で7〜8に縮小されていた電話番号・延長・高さ等が10になる）。

6. 重要な決定事項

  • データ連携方式: クラウドDB不使用。ASP（現場クラウドONE）をファイル置き場として利用。
  • App AとApp Bのフィールド整合: fieldMasterのキー名はApp AのJZIP出力のキー名と完全一致させること。
  • Excel帳票をAppBに統合: Python exe版はウイルス検知問題で断念。HTMLアプリとしてAppBに組み込む方針に確定。
  • GeoJSON/KMLのラベル問題: 地理院地図・GoogleEarthともにLineStringにはラベルが表示されない。起点のみ版を別出力として提供。
  • JZIP一括出力: 現状は個別のみ。要望があれば対応。
  • jzip_spec.html: AppAスレッドで管理。AppA・AppB両スレッドに毎回渡す。
  • PDF帳票の1行枠は「クリップしない・縦中央・10を基準に幅で縮小」（Phase 13.43）: 端末のフォント差で縦位置が変わっても文字が欠けないことを優先する。
  • Excel帳票の改善は優先度を下げる: Excelはセル・図形の自由度が高く後から対応できるため、当面はPDF帳票の改良を優先する（Phase 13.43時点の方針）。
